Services and Routes

In Kong Gateway a Service is an abstraction of an upstream application, and each Service may have one or more Routes attached to it for matching incoming client requests.

Creating a Service

Use the Admin API to register an upstream application as a Service so the gateway knows where to forward requests once a Route has matched them successfully.

curl -X POST http://localhost:8001/services --data name=example
  • Routes match on paths and hosts
  • Each Route belongs to one Service
FieldDescription
pathsPath prefixes that match

Verifying the Configuration

Send a request through the proxy port to confirm the gateway forwards it to the upstream application correctly and returns the expected response body to the caller.

If the request fails, check that the Route paths match the request and that the Service URL points at a host reachable from inside the gateway container itself.

Troubleshooting Common Errors

A 404 from the proxy port usually means no Route matched the request, while a 502 indicates the Route matched but the upstream Service could not be reached at all.
